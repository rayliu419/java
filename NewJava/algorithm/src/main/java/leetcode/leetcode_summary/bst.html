学习笔记

一、核心心法

树题的核心是 递归语义 — 想清楚你的函数"返回什么、做什么"，剩下的就是把这个语义翻译成代码。

递归的三个层次

难度遍历方式适用场景
基础前序 / 中序 / 后序带 pre 的递归，三种遍历都是"三板斧"
进阶定义清晰语义的递归函数根据语义实现，不必纠结遍历顺序
困难后序 + 融合计算需要同时算两个结果（如高度+直径），合并到一个递归中。其实还是定义递归语义，怎么得到需要这么定义是个难点

怎么解复杂的树题

  1. test case 驱动 — 树的节点用不同的值，方便追踪递归栈
  2. 把要做的 N 件事先列出来 — 复杂的后序往往要同时做多件事，列清楚再写
  3. 融合计算 — 性能优化的关键手法（见下方 543/124 详解）

几个重要的识别模式

模式说明
后序修正解递归函数的返回值只有在根调用时才是最终结果（LCA 高效解法）
直径型问题答案可能跨越左右子树，也可能在单侧子树中 — 需要同时往上传和全局记

Insert into a BST（701）⭐⭐⭐ / Delete Node in a BST（450）⭐⭐⭐⭐

核心：递归函数语义 = "返回调整好的子树根" 定义完成后，考虑在不同层次需要做的事情。root.left/right = recursive_method 是关键。这种写法普遍用于复杂的树问题。

insertIntoBST 和 deleteNode 都是同一个语义。为什么要这么设计？
树的父子关系通过 left/right 指针维系，任何增删操作都可能改变这个指针的指向。
用返回值让每一层自动重新挂接子节点，就不需要传 parent 引用、判断方向、处理根节点无父节点的边界。

💡 这是一个需要明确定义递归函数语义才能很容易写的典型例子。

Flatten Binary Tree to Linked List（114）

  • 和 701/450 同样的模式：定义递归函数语义 → 用 root.left/right = recursive() 挂接结果

递归语义：flattenTree(root) — 展平以 root 为根的子树，并返回展平后的根（即 root 本身）

调用完成后保证：

  1. 子树已按前序遍历顺序展平成一条右斜链
  2. 所有节点的 left = null
  3. right 指向前序的下一个节点
  4. 返回值永远等于入参 root（和 deleteNode 不同，deleteNode 可能返回新根）
flattenTree(root):
  root.left = flattenTree(root.left)   ← 左子树已展平，结果接回来
  root.right = flattenTree(root.right) ← 右子树已展平，结果接回来
  // 处理当前节点：三种情况
  // 叶子 / 只有右子树 → 直接返回
  // 只有左子树 → 移到右边，left 置 null
  // 左右都有 → 左子树的最右节点接右子树，左移右，left 置 null
💡 与 deleteNode/insertIntoBST 的区别：它们的返回值可能是新根（删除/插入改变了根），而 flatten 的根不会变。但"用返回值让上层重新挂接"的手法一样。

LCA（Lowest Common Ancestor）— 两种实现对比

BST 中的 LCA 很简单（利用大小关系剪枝），但普通二叉树的 LCA 有两种不同的实现思路，理解其差异有助于掌握递归语义的设计。
⚠️ 重要前提：如果不是确定 p、q 一定在树中，需要先遍历一次确认它们存在，再执行 LCA 算法。否则「直接返回 + 混合语义」的 修正解思路（版本二）可能返回错误的 LCA（例如 q 不存在却返回了 p）。这个前提对 二叉树 和 K-ary 树 的修正解都适用。

两个实现都在 BST.java 中：

版本一：result 包装器 + 剪枝

TreeNode lowestCommonAncestor(root, p, q) {
    TreeNode[] result = new TreeNode[1];
    LCA(root, p, q, result);
    return result[0];
}

TreeNode LCA(root, p, q, result) {
    if (root == null || result[0] != null)
        return null;
    TreeNode left = LCA(root.left, p, q, result);
    TreeNode right = LCA(root.right, p, q, result);
    boolean foundSelf = root.val==p.val
                     || root.val==q.val;
    if (foundSelf && (left!=null||right!=null))
      { result[0]=root; return root; }
    if (left!=null && right!=null)
      { result[0]=root; return root; }
    if (foundSelf) return root;
    return left != null ? left : right;
}
  • 递归语义纯粹：返回值 = "是否找到 p/q"
  • result[0] 独立存 LCA
  • p/q 缺失时 result[0] 保持 null
  • result[0] != null 后整树剪枝

版本二：直接返回 + 混合语义

TreeNode lowestCommonAncestor2(root, p, q) {
    if (root == null) return null;
    if (root.val == p.val) return root;
    if (root.val == q.val) return root;

    TreeNode left = lowestCommonAncestor2(
        root.left, p, q);
    TreeNode right = lowestCommonAncestor2(
        root.right, p, q);
    if (left!=null && right!=null) return root;
    if (left != null) return left;
    if (right != null) return right;
    return null;
}
  • 返回值混合：可能是 p/q 也可能是 LCA
  • 依赖 p/q 一定存在
  • 找到 p/q 后只剪下方，兄弟仍需遍历
  • 代码简洁，适合竞赛/刷题场景

核心对比

维度result 包装器版直接返回版
递归语义单一：返回值 = 是否找到 p/q混合：可能是 p/q 也可能是 LCA
结果存取result[0] 独立存储直接用返回值传递
p/q 缺失正确（result[0] = null）错误（返回已找到的节点）
剪枝时机result[0] 赋值后整树剪枝找到 p/q 后只剪下方子树
遍历范围找到 LCA 后立即停止找到 p/q 后仍需遍历兄弟子树
代码复杂度稍高（需要包装器）简洁
适用场景安全性优先，需处理异常情况竞赛/刷题，假设 p/q 一定存在

K-ary Tree LCA（多叉树最近公共祖先）

BST 和二叉树的 LCA 思路推广到多叉树：每个节点有 List<KTreeNode> children，本质是"在 N 个分支中寻找 p 和 q"。

多叉树的 LCA 是二叉树 LCA 的直接推广。二叉树只有两个分支（left / right），多叉树则有 N 个分支（children）。

节点定义

class KTreeNode {
    int val;
    List<KTreeNode> children;
    KTreeNode(int val) { this.val = val; this.children = new ArrayList<>(); }
}

代码实现

KTreeNode lowestCommonAncestor(KTreeNode root, KTreeNode p, KTreeNode q) {
    if (root == null) return null;
    if (root.val == p.val || root.val == q.val) return root;

    List<KTreeNode> candidates = new ArrayList<>();
    for (KTreeNode child : root.children) {
        KTreeNode result = lowestCommonAncestor(child, p, q);
        if (result != null) candidates.add(result);
    }

    if (candidates.size() >= 2) return root;        // p 和 q 在不同子树
    if (candidates.size() == 1) return candidates.get(0);  // 单侧返回
    return null;  // 没找到
}

算法逻辑

  1. 递归语义：返回值 = 在该子树中找到的 p/q/LCA。与二叉树 LCA 版二（直接返回版）完全一致。
  2. 当前节点就是 p 或 q → 直接返回自己，它是潜在的 LCA。
  3. 遍历所有孩子：统计所有孩子返回的非 null 结果。
  4. ≥ 2 个非 null：p 和 q 分布在不同的孩子子树中 → 当前节点就是 LCA。
  5. 恰好 1 个非 null：把该孩子的结果往上传递。
  6. 全为 null：该子树不存在 p 或 q，返回 null。

与二叉树 LCA 的对比

维度二叉树 LCAK-ary 树 LCA
分支数量固定 2（left / right）N（children 列表）
判断条件left != null && right != null → 当前是 LCAcandidates.size() >= 2 → 当前是 LCA
返回值逻辑三目运算符 / if-else 链收集 candidates 列表统一判断
复杂度O(n)O(n)（每个节点仍只访问一次）
💡 核心洞察：二叉树 LCA 的 left != null && right != null → return root 本质是"在两个分支中各找到了目标"。在多叉树中推广为"在至少两个孩子子树中各找到了目标"。

解法二：路径比较法

另一种思路：分别找出 root → p 和 root → q 的路径，两条路径最后一个相同节点即为 LCA。
KTreeNode lowestCommonAncestor2(KTreeNode root, KTreeNode p, KTreeNode q) {
    List<KTreeNode> pathP = new ArrayList<>();
    List<KTreeNode> pathQ = new ArrayList<>();
    if (!findPath(root, p, pathP) || !findPath(root, q, pathQ)) {
        return null;
    }
    int i = 0;
    while (i < pathP.size() && i < pathQ.size()
           && pathP.get(i) == pathQ.get(i)) {
        i++;
    }
    return pathP.get(i - 1);
}

boolean findPath(KTreeNode root, KTreeNode target, List<KTreeNode> path) {
    if (root == null) return false;
    path.add(root);
    if (root.val == target.val) return true;
    for (KTreeNode child : root.children) {
        if (findPath(child, target, path)) return true;
    }
    path.remove(path.size() - 1);
    return false;
}

算法步骤：

  1. findPath 做 DFS 查找 target，用 path 记录沿途节点，找到后返回 true
  2. 没找到时回溯：path.remove(path.size() - 1) 移除当前节点
  3. 得到两条路径后，从头遍历直到遇到第一个不同节点，其前一个就是 LCA
维度解法一（递归搜索）解法二（路径比较）
时间复杂度O(n)O(n)
空间复杂度O(h)（递归栈深度）O(n)（两条路径，最差 O(n)）
第一次遍历找到 p/q 后直接返回，不再往下递归DFS 仍在回溯，但已找到 target 时兄弟子树不遍历
代码可读性高度抽象，递归语义需理解直观，路径比较易于理解
适用场景只需 LCA，无需路径信息额外需要路径信息的场景

二叉树序列化（LeetCode 297）⭐⭐⭐⭐

序列化是将二叉树编码为字符串，反序列化是从字符串还原出原树。面试高频题。

1. 前序遍历序列化

序列化过程：按前序（根→左→右）递归遍历，节点值用 , 分隔，空节点标记为 #。

    30
   /  \
  10   20
 /    /  \
50   45  35

→ "30,10,50,#,#,#,20,45,#,#,35,#,#"

反序列化核心：维护一个全局索引，按前序顺序消费字符串数组。

当前元素操作
#返回 null，索引+1（空子树）
数字创建节点，索引+1，递归构建左右子树
💡 关键 insight：序列化时，当前元素的下一个和下两个一定是当前节点的左孩子和右孩子（只要当前不为 #）。前序遍历的顺序天然保证了这一点。

反序列化递归语义——怎么理解才好写

反序列化的递归函数定义这个契约：

	deserialize(指针):
	  从指针当前位置开始，恰好消费掉「一棵树」的序列化数据
	  返回这棵树的根节点（或 null）
	  指针停在「这棵树」之后的位置

它和 serialize 是完全对称的——序列化是先写根再递归左右，反序列化就是先读根再递归左右，代码结构一模一样：

序列化

	void serialize(Node root, sb) {
	    if (root == null) {
	        sb.append("#,");
	        return;
	    }
	    sb.append(root.val).append(",");
	    serialize(root.left, sb);
	    serialize(root.right, sb);
	}

反序列化

	Node deserialize(arr, c) {
	    if (arr[c.index].equals("#")) {
	        c.index++;
	        return null;
	    }
	    Node node = new Node(arr[c.index]);
	    c.index++;
	    node.left = deserialize(arr, c);
	    node.right = deserialize(arr, c);
	    return node;
	}

理解方式——把数组看成嵌套括号，每个 deserialize() 调用吃掉自己的一对括号：

	原始:  30, 10, 50, #, #, #, 20, 45, #, #, 35, #, #
	括号:  30, [10, [50, #, #], #],  [20, [45, #, #], [35, #, #]]
	            ├──左子树──┤            ├─────右子树────────┤
  • # 是递归终止信号：遇到就返回 null，指针+1
  • 不是 #：当前值就是子树的根，创建节点，指针+1，递归两次——第一次自动消费左子树的所有元素，第二次自动消费右子树的所有元素
  • 不用关心递归内部怎么停的，只要相信：deserialize(left) 会恰好消费掉左子树的所有元素，指针停在正确位置
❓ 为什么中序不行？ 前序序列化是 [根, 左子树..., 右子树...]，反序列化一上来就读到根，然后递归消费左右——顺序一致。中序是 [左子树..., 根, 右子树...]，反序列化一上来不知道哪里是根，无法唯一确定。

2. 层序遍历序列化

BFS 逐层遍历，用占位符标记空位，逐层推进直到下一层全为空。

    1
   / \
  2   3
 /
4

→ "1,2,3,4,#,#,#"

反序列化：用数组索引映射，globalIndex 指向左右孩子位置，遇到 # 跳过。

3. 为什么中序遍历不行？

两种不同形态的树可能产生完全相同的中序序列：

树 A

  1
 /
2

树 B

2
 \
  1

中序遍历都是 "2,1"，无法确定根的位置 → 反序列化不唯一。
