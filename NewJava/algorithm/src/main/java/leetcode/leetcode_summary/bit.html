位操作总结

核心思路：位操作是 CPU 最底层的运算，天然具有 O(1) 时间、O(1) 空间的优势。位运算的核心模式包括：用二进制编码压缩状态（如用 int 的 32 位表示 32 个布尔值）、利用位掩码跳过循环（如 n & (n-1) 消除最低位的 1）、异或的对称抵消性质（a ^ a = 0, 0 ^ a = a）。掌握这些模式，可以在特定题目中实现惊人的常数优化。

常用位技巧

设置某位为 1

bit_fld |= (1 << n);   // 将第 n 位置 1

清除某位（置 0）

bit_fld &= ~(1 << n);  // 将第 n 位清零

反转某位（Toggle）

bit_fld ^= (1 << n);   // 第 n 位 0 变 1，1 变 0

测试某位

bool isSet = bit_fld & (1 << n);   // 非 0 则第 n 位为 1
提示：测试某位时，是否需要 1u（无符号 1）取决于语言和位数。在 C/C++ 中，如果 n == 31，1 << 31 在有符号 int 中是未定义行为（或得到负数）。Java 中 1 << 31 是合法的，结果为 Integer.MIN_VALUE，且 & 运算后判断 != 0 即可，无需强转无符号。建议统一用 != 0 判断。

判断 2 的幂

核心心法：2 的幂的二进制表示中恰好只有一个 1。x & (x - 1) 去掉这个 1 后结果应为 0。 
bool isPowerOfTwo = x && !(x & (x - 1));

拆解：

  • x && — 排除 x == 0（0 不是 2 的幂）。注意 -2147483648（即 Integer.MIN_VALUE）也不是 2 的幂，因为它只有一个 1 但表示的是负数。不过如果函数是处理有符号 int，x > 0 && !(x & (x-1)) 更安全。
  • !(x & (x - 1)) — 如果二进制只有一个 1，去掉它后结果为 0。

反转二进制位（Reverse Bits）

注意：此题看似简单，但容易在细节上出错——特别是循环中的移位顺序和符号位处理。 
int reverseBits(int n) {
    int y = 0;
    int digit = 0;
    int x = n;
    for (int i = 0; i < 32; i++) {
        y = y << 1;          // 先腾出最低位
        digit = x & 1;       // 取 x 的最低位
        y = y | digit;       // 写入 y 的最低位
        x = x >> 1;         // x 右移，下一位进入最低位
    }
    return y;
}

关键细节：

  • 为什么 temp 不行？——如果先把 x 保存到 temp 然后操作 temp，实际效果和直接操作 x 没有区别。问题一般不出在变量名上，而是出在移位顺序上：y = y << 1 必须在 y = y | digit 之前，否则第一次循环会丢失第一个 bit。
  • 有符号右移 >> 对负数会在高位补 1。但在 reverseBits 中，我们只需要取最低位，高位填 1 或 0 不影响 x & 1 的结果。不过如果在意，可以用无符号右移 >>>。

重复 DNA 序列（Repeated DNA Sequence）

核心心法：题目要求找所有出现次数 ≥ 2 的长度为 10 的子串。直观上用 HashMap 会 MLE。关键优化：将 ACGT 编码为 2-bit 二进制，用 int 代替 String 作为 HashMap 的 key。

编码方案

A -> 00
C -> 01
G -> 10
T -> 11

一个长度为 10 的子串需要 20 个二进制位，恰好能放入一个 int（32 位）中：

例：ACGTACGTAC -> 00011011000110110001
    AAAAAAAA   -> 00000000000000000000

空间优化原理

  • 20 位二进制数共有 220 = 1,048,576 种可能。
  • 可以用一个 bool 数组 代替 HashMap：bool hashTable[1024 * 1024];
  • 第一次遇到时设置为 true，第二次遇到时即为重复。
  • 相比 HashMap（需要存完整字符串 + 哈希表开销），数组方式几乎零额外内存。
总结：当数据空间有限（如本题 220 种组合），用位编码 + 数组替代 HashMap 是经典的降低常数和内存的技巧。类似的思路在 布隆过滤器 和 BitSet 中也有应用。

数字范围按位与（Bitwise AND of Numbers Range）

给定范围 [m, n]（0 ≤ m ≤ n ≤ 231 - 1），返回范围内所有数字的按位与。

解法 1：暴力法

int res = m;
for (int i = m + 1; i <= n; i++) res &= i;

时间 O(n - m)，当范围很大时（如 m = 1, n = 231 - 1）直接超时。

解法 2：找公共左前缀

核心心法：从 m 到 n 的范围内，每个 bit 只要出现过 0，最终结果中该位就是 0。当二进制数从 xxxx0zzzz 跳到 xxxx10000 时，低位全部归零再向上增长——这意味着高位不变的公共前缀就是答案，低位全为 0。

假设 m 和 n 的二进制分别是：

m = xxxx0zzzz...
n = xxxx1yyyy...

当 xxxx0zzzz 不断 +1 直到变成 xxxx10000 时，所有低位都被 AND 成 0。因此最终结果是 m 和 n 的公共二进制左前缀 + 低位补 0。

int rangeBitwiseAnd(int m, int n) {
    int shift = 0;
    while (m != n) {
        m >>>= 1;   // 不断右移，直到 m 和 n 相等
        n >>>= 1;   // 注意用无符号右移避免符号位干扰
        shift++;
    }
    return m << shift;  // 左移回原来的位置，低位补 0
}
易错点：如果 m 和 n 都是负数或有符号数，右移时要用 >>>（无符号右移）以免符号位被复制。Java 中 int 是 32 位有符号，>> 对负数高位补 1 会破坏循环条件。

复习要点：
  1. 异或 (^) 是位运算中最"灵性"的操作——去重、交换、找不同，很多题目围绕它展开。
  2. n & (n-1) 是位运算的"核武器"——清最低位的 1，用在计数、2 的幂判断、枚举子集等场景。
  3. 编码压缩——当元素集合很小（如 ACGT 只有 4 种），用二进制编码代替字符串/对象来降低内存。
  4. 找公共前缀——区间 AND 的本质是找二进制表示的共同前缀。
