回溯去重：startIndex 与非递减下标序列

回溯组合题中，startIndex 解决了一个核心矛盾：组合不关心顺序，但回溯的递归搜索天然会枚举所有排列。从 i=0 开始遍历等价于在全排列空间中搜索，同一组数字的不同排列都会出现。startIndex 通过强制下标序列非递减，将搜索空间从 n! 压缩到组合空间的 2ⁿ / C(n,k)，彻底消除排列重复。

1. 有 Bug 的 case

candidates = [2, 3, 6, 7], target = 7

错误写法：每次递归从 i = 0 开始遍历

for (int i = 0; i < candidates.length; i++) {
    ...
    combinationSum(finalResult, cur, candidates, target - candidates[i]);
    ...
}

输出：[2,2,3]、[2,3,2]、[3,2,2]、[7]

{2,2,3} 这组数字产生了 3 种排列，期望只有 [2,2,3] 一个解。

2. 根因：排列空间 vs 组合空间

每次从 i = 0 开始遍历，意味着递归的每一层都能回头选择之前已经选过的下标。这等价于在全排列空间中搜索——排列关心"按什么顺序选"，不关心"选了哪些数"。

本质：当你用排列的搜索方式（每层全量遍历）去做组合题，就会得到"不该出现的排列"。

3. 修复：startIndex

void backtrack(..., int start) {
    if (target == 0) { res.add(new ArrayList<>(cur)); return; }
    for (int i = start; i < candidates.length; i++) {
        if (target - candidates[i] < 0) continue;
        cur.add(candidates[i]);
        backtrack(res, cur, candidates, target - candidates[i], i);
        cur.remove(cur.size() - 1);
    }
}

两处改动：循环起始改为 start，递归传递 i（不是 i+1，因为允许重复用当前元素）。

4. 核心原理：非递减下标序列

startIndex 约束下标序列单调不减。选了下标 1 之后不能再回头选 0。同一组数字只保留下标递增的"规范形"，其他排列组合被自动排除。

下标序列对应组合是否非递减startIndex 能否产生
[0, 0, 1]2+2+3✅✅
[0, 1, 0]2+3+2❌（1→0）❌
[1, 0, 0]3+2+2❌（1→0）❌

洞察：组合的解由下标的多重集唯一确定。将下标按非递减排序后，每个多重集有且仅有一个规范形。startIndex 保证回溯只在规范形空间中搜索，自然零重复。

5. 与排列的对比

组合（Combination）排列（Permutation）
能否回头❌ 产生重复✅ 产生新解
遍历范围start ~ n-10 ~ n-1（跳过已选）
空间大小C(n,k) / 2ⁿn!

区分判断：[2,3] 和 [3,2] 在你的问题语境下是同一个解还是两个解？前者用 startIndex，后者用 used[] 数组。

总结与启发

startIndex 的本质是对搜索空间施加"下标单调性"约束。

这个约束将排列空间（n!）降维到组合空间（2ⁿ / C(n,k)），消除重复的同时保持了回溯搜索的完整性。

更一般的模式：几乎所有组合类回溯题（组合总和、子集、有重复元素的组合）的去重方案，最终都归结为同一条原则：

当解空间不关心元素顺序时，在递归中强制下标单向移动，就是最自然的去重手段。

思考链路总结：

  1. 出现排列重复 → 检查每层递归的循环起点
  2. 若从 i=0 开始 → 相当于在排列空间搜索
  3. 加 startIndex → 强制下标非递减 → 回到组合空间
  4. 允许重复选同一元素 → 递归传 i；不允许 → 传 i+1
