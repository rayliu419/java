基础概念：什么是「旋转点」？

旋转点就是左段的最后一个元素，即升序关系在此处断裂的位置。

例如数组 [4, 5, 6, 7, 0, 1, 2]，元素 7 就是旋转点（index 3），因为 7 > 0 打破了升序。

旋转数组由两段拼接而成，旋转点是两段的分界点：

左段（值较大）：[4, 5, 6, 7]，末尾 7 为旋转点
右段（值较小，含最小值）：[0, 1, 2]，开头 0 为最小值

特征：arr[i] > arr[i+1] 的唯一位置 i，即旋转点
最小值 = 旋转点的下一个元素 = 右段的第一个元素
二分查找的目标：找到指向右段第一个元素的位置
问题 1：为什么最小值一定在未排序的区间？

因为未排序说明这个区间跨过了旋转点（pivot），而旋转点就是最小值所在的位置。

旋转后的数组由两个递增段拼接而成。检查任意区间是否递增，等价于检查它是否包含旋转点。只要区间是递增的，旋转点（最小值）就不在里面，可以安全丢弃。

实质：nums[mid] > nums[high] → 右半边不是递增的 → 跨过了旋转点 → 最小值在右边
nums[mid] < nums[high] → 右半边是递增的 → 没有旋转点 → 最小值在左边（或就是 mid）
问题 2：为什么不能用 nums[low] < nums[mid] 判断？为什么 nums[mid] < nums[high] 就没有这个问题？

因为 nums[low] < nums[mid] 为 true 时可能对应两种截然不同的情况，搜索方向完全相反：

情况 A（正常）：旋转点在右边，左半边有序、最小值在右边 → 应往右搜索 ✅

情况 B（陷阱）：low 和 mid 都已经进入了右段（经过几轮二分后），此时左半边有序但最小值在 mid 的左前方 → 往右搜索就错过了 ❌

具体例子：数组 [4,5,6,7,0,1,2] 走到第 2 轮时 low=4(0) mid=5(1) high=6(2)，0 < 1 但 low/mid 都在右段，最小值 0 在 mid 左边。用 nums[mid] < nums[high] 则得出 1 < 2 → 右半边有序 → 往左搜，正确找到 0。

而 nums[mid] < nums[high] 为 true 时，指向必定是数组的末尾递增段（右段），不包含旋转点，方向唯一确定：最小值在左边。

不对称的原因：用 nums[high] 比较，搜索方向始终向最小值坍缩；用 nums[low] 比较，在"未旋转"和"已进入右段"两种场景下会给出相反的方向。

问题 3：二分以后，「左段 > 右段」这个性质还成立吗？

只要当前子范围仍然跨两段（包含旋转点），性质就继承成立。

整个数组 [3, 4, 5, 6, 7, 0, 1, 2]：左段 [3,4,5,6,7] > 右段 [0,1,2] ✓

第一轮后缩到 low=4，范围 [7, 0, 1, 2]：左段 [7] > 右段 [0,1,2] ✓ —— 它自己就是一个小号的旋转有序数组

第二轮后缩到 [7, 0]：左段 [7] > 右段 [0] ✓

一旦搜索范围不再跨段（收缩到纯右段），说明找到了——纯递增序列的最左端就是最小值，算法结束。

每次二分都在做同一件事：判断旋转点还在不在当前范围内。
nums[mid] > nums[high] → 旋转点在右侧，跨段性质保持 → 向右搜索
nums[mid] < nums[high] → 旋转点已被排除，只剩递增序列 → 向左找最小值
问题 4：为什么 mid < high 时保留 mid，mid > high 时跳过 mid？

因为最小值永远在右段，问题就是判断 mid 落在左段还是右段：

当 nums[mid] < nums[high]：mid 在右段 ✅ → mid 可能是最小值 → 保留（high = mid）

当 nums[mid] > nums[high]：mid 在左段 ❌ → mid 不可能是最小值（利用"左段所有值 > 右段所有值"的性质）→ 跳过（low = mid + 1）

总结：nums[mid] < nums[high] → mid 在右段，可能是 min，保留
         nums[mid] > nums[high] → mid 在左段，不可能是 min，跳过

不对称的本质：右段可能包含 min，所以只能从右段左侧收窄（high = mid）； 左段一定不含 min，所以可以直接从左段右侧跳过（low = mid + 1）
