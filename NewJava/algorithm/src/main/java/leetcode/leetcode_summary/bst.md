## 核心套路

```
验证 BST      → 中序递增 / 区间约束
第 K 小       → 中序遍历到第 K 个
删除          → 找到节点 → 三种情况处理
构建 BST      → 有序数组二分递归
LCA           → 利用 BST 大小关系直接判断
DP/计数       → 卡特兰数 / 区间 DP
迭代器        → 栈模拟中序遍历
搜索/插入     → 比较大小决定方向
中序统计类    → 中序遍历 + 相邻比较（最小差/众数）
恢复          → 中序遍历找逆序对
修剪          → 区间递归裁剪
累加树        → 逆中序遍历累加
序列化/反序列化 → 前序递归序 + # 空标记
```

## 学习笔记

### 一、核心心法

> 树题的核心是 **递归语义** — 想清楚你的函数"返回什么、做什么"，剩下的就是把这个语义翻译成代码。

#### 递归的三个层次

| 难度 | 遍历方式 | 适用场景                                                 |
|------|----------|------------------------------------------------------|
| 基础 | **前序 / 中序 / 后序** | 带 pre 的递归，三种遍历都是"三板斧"                                |
| 进阶 | **定义清晰语义的递归函数** | 根据语义实现，不必纠结遍历顺序                                      |
| 困难 | **后序 + 融合计算** | 需要同时算两个结果（如高度+直径），合并到一个递归中。其实还是定义递归语义，怎么得到需要这么定义是个难点 |

#### 怎么解复杂的树题

1. **test case 驱动** — 树的节点用不同的值，方便追踪递归栈
2. **把要做的 N 件事先列出来** — 复杂的后序往往要同时做多件事，列清楚再写
3. **融合计算** — 性能优化的关键手法（见下方 543/124 详解）

#### 几个重要的识别模式

| 模式 | 说明 |
|------|------|
| **后序修正解** | 递归函数的返回值只有在根调用时才是最终结果（LCA 高效解法） |
| **直径型问题** | 答案可能跨越左右子树，也可能在单侧子树中 — 需要同时往上传和全局记 |
| **双节点问题** | 先检查两个目标节点是否存在 |
| **非递归遍历** | 面试很少考，**重点放递归** |

#### 非递归实现树的遍历

非递归主要是用栈。其转换方法可以考虑联系recursive-to-iteration.md。尤其是前序和中序。复杂后序问题用非递归有点复杂了。

#### Insert into a BST（701） ⭐⭐⭐ / Delete Node in a BST（450） ⭐⭐⭐⭐
> 核心：**递归函数语义 = "返回调整好的子树根"** 定义完成后，考虑在不同层次需要做的事情。**root.left/right = recursive_method**是关键。
> 这种写法普遍用于复杂的树问题。

`insertIntoBST` 和 `deleteNode` 都是同一个语义。为什么要这么设计？
**树的父子关系通过 left/right 指针维系，任何增删操作都可能改变这个指针的指向。** 
用返回值让每一层自动重新挂接子节点，就不需要传 parent 引用、判断方向、处理根节点无父节点的边界。

> 这是一个需要明确定义递归函数语义才能很容易写的典型例子。

#### Flatten Binary Tree to Linked List（114）
- 和 701/450 同样的模式：**定义递归函数语义 → 用 `root.left/right = recursive()` 挂接结果**

  递归语义：**`flattenTree(root)` — 展平以 `root` 为根的子树，并返回展平后的根（即 root 本身）**

  调用完成后保证：
  1. 子树已按**前序遍历**顺序展平成一条右斜链
  2. 所有节点的 `left = null`
  3. `right` 指向前序的下一个节点
  4. 返回值永远等于入参 `root`（和 deleteNode 不同，deleteNode 可能返回新根）

  ```
  flattenTree(root):
    root.left = flattenTree(root.left)   ← 左子树已展平，结果接回来
    root.right = flattenTree(root.right) ← 右子树已展平，结果接回来
    // 处理当前节点：三种情况
    // 叶子 / 只有右子树 → 直接返回
    // 只有左子树 → 移到右边，left 置 null
    // 左右都有 → 左子树的最右节点接右子树，左移右，left 置 null
  ```

  > 与 deleteNode/insertIntoBST 的区别：它们的返回值可能是新根（删除/插入改变了根），而 flatten 的根不会变。但"用返回值让上层重新挂接"的手法一样。

#### 二叉树的直径（543） ⭐⭐⭐⭐

直径可能来源于三个地方：

```
直径 = max(左子树直径, 右子树直径, 左高度 + 右高度)
```

| 做法 | 复杂度 | 问题 |
|------|--------|------|
| 分别写函数算高度和直径 | O(n²) | 递归中套递归，大量重复 |
| **融合到一个递归函数** | **O(n)** | 同时返回高度，更新全局直径 |

> ⚠️ **Same Tree** 例外：主函数是比较两棵树，递归是比较两个节点 — 语义不同，无法融合

#### Binary Tree Maximum Path Sum（124） ⭐⭐⭐⭐⭐
> 思路类似树的直径，**务必仔细看负值处理！**

递归函数的语义：
- **当前节点返回**：以 x 子树中某节点为起点，到 x 结束的最大路径和（只能走一侧）
- **全局更新**：路径可能横跨 x 的左右子树（左+根+右），但这种情况**不能往上接了**
- 负值贡献 → 直接舍弃（`max(0, leftGain)`）

#### Subtree of Another Tree（572） ⭐⭐

将树**编码成字符串**，后序遍历：

```
encode(root) = encode(root.left) + height(root) + encode(root.right)
```

- 先对小树编码，再对大树后序遍历编码

### 二叉树序列化（LeetCode 297）⭐⭐⭐⭐

> 序列化是将二叉树编码为字符串，反序列化是从字符串还原出原树。面试高频题。

#### 1. 前序遍历序列化

**序列化过程**：按前序（根→左→右）递归遍历，节点值用 `,` 分隔，空节点标记为 `#`。

```
    30
   /  \
  10   20
 /    /  \
50   45  35
```
→ `"30,10,50,#,#,#,20,45,#,#,35,#,#"`

**反序列化核心**：维护一个全局索引，按前序顺序消费字符串数组。

| 当前元素 | 操作 |
|---------|------|
| `#` | 返回 null，索引+1（空子树） |
| 数字 | 创建节点，索引+1，递归构建左右子树 |

关键 insight：**序列化时，当前元素的下一个和下两个一定是当前节点的左孩子和右孩子**（只要当前不为 `#`）。这是因为前序遍历的顺序天然保证了这一点。


##### 反序列化递归语义——怎么理解才好写

反序列化的递归函数定义这个**契约**：

```
deserialize(指针):
  从指针当前位置开始，恰好消费掉「一棵树」的序列化数据
  返回这棵树的根节点（或 null）
  指针停在「这棵树」之后的位置
```

它和 `serialize` 是**完全对称**的——序列化是先写根再递归左右，反序列化就是先读根再递归左右，**代码结构一模一样**：

```java
// 序列化                           // 反序列化
void serialize(Node root, sb) {     Node deserialize(arr, c) {
    if (root == null) {                 if (arr[c.index].equals("#")) {
        sb.append("#,");                    c.index++;
        return;                             return null;
    }                                   }
    sb.append(root.val).append(",");    Node node = new Node(arr[c.index]);
    serialize(root.left, sb);           c.index++;
    serialize(root.right, sb);          node.left = deserialize(arr, c);
}                                       node.right = deserialize(arr, c);
                                        return node;
                                    }
```

理解方式——把数组看成**嵌套括号**，每个 `deserialize()` 调用吃掉自己的一对括号：

```
原始:  30, 10, 50, #, #, #, 20, 45, #, #, 35, #, #
括号:  30, [10, [50, #, #], #],  [20, [45, #, #], [35, #, #]]
            ├──左子树──┤            ├─────右子树────────┤
```

- `#` 是递归终止信号：遇到就返回 null，指针+1
- 不是 `#`：当前值就是**子树的根**，创建节点，指针+1，递归两次——第一次**自动消费左子树的所有元素**，第二次**自动消费右子树的所有元素**
- **不用关心递归内部怎么停的**，只要相信：`deserialize(left)` 会恰好消费掉左子树的所有元素，指针停在正确位置

为什么中序不行？前序序列化是 `[根, 左子树..., 右子树...]`，反序列化一上来就读到根，然后递归消费左右——顺序一致。中序是 `[左子树..., 根, 右子树...]`，反序列化一上来不知道哪里是根，无法唯一确定。

#### 2. 层序遍历序列化

BFS 逐层遍历，用占位符标记空位，逐层推进直到下一层全为空。

```
    1
   / \
  2   3
 /
4
```
→ `"1,2,3,4,#,#,#"`

**反序列化**：用数组索引映射，`globalIndex` 指向左右孩子位置，遇到 `#` 跳过。

#### 3. 为什么中序遍历不行？

两种不同形态的树可能产生完全相同的中序序列：

```
  1         2
 /           \
2             1
```
中序遍历都是 `"2,1"`，无法确定根的位置 → **反序列化不唯一**。

#### 4. 两种方案对比

| 维度 | 前序序列化 | 层序序列化 |
|------|-----------|-----------|
| 实现难度 | 简单（递归） | 中等（BFS + 占位符） |
| 反序列化 | 递归消费数组 | 索引映射建树 |
| 空间 | O(n) 递归栈 | O(n) 队列 + 缓存 |
| 空节点标记 | `#` | `#` 或占位符对象 |
| LeetCode 297 | ✅ 可解 | ✅ 可解 |
| 单节点树 | `val,#,#`（略冗余） | `val`（更紧凑） |
