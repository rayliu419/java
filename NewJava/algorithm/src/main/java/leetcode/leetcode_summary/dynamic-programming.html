学习笔记

一、核心思想

动态规划的本质是用空间换时间：把大问题拆成可重复的子问题，记录子问题答案避免重复计算。

DP 五步法（解题框架）

  1. 定义状态：dp[i][j] 表示什么？一定要明确语义
  2. 状态转移：dp[i][j] 怎么从之前的状态推导过来？
  3. 初始化：base case 是什么？（dp[0]、dp[i][0] 等）
  4. 遍历顺序：从小到大？从大到小？左上到右下？
  5. 返回结果：最终答案在 dp 的哪个位置？
五步法中状态定义是最关键的一步，状态定义对了，转移往往自然而出。
💡 初始化技巧：dp 多开一个维度，简化边界处理

这是 DP 编码中最实用也最容易被忽视的技巧。

核心思想：把 dp 数组的索引与问题数据的索引错开一位，让 dp[i] 对应 data[0..i-1]，dp[0] 自然代表「空集/空串」的 base case。这样循环体里不需要写 if 判断边界。

✅ LCS 的对比

// ❌ 如果没有多开一位，代码会变成这样：
// 需要手动处理 i=0 或 j=0 的情况
int[][] dp = new int[m][n];
for (int i = 0; i < m; i++) {
    for (int j = 0; j < n; j++) {
        if (text1.charAt(i) == text2.charAt(j)) {
            dp[i][j] = (i==0 || j==0 ? 0 : dp[i-1][j-1]) + 1;
            //          ^^^^^^^^^^^^^^^^^^^^^^^^^^^^ 边界判断污染了核心逻辑
        } else {
            int up = i==0 ? 0 : dp[i-1][j];
            int left = j==0 ? 0 : dp[i][j-1];
            dp[i][j] = Math.max(up, left);
        }
    }
}

// ✅ 多开一位，base case 自然归零，循环从 1 开始
int[][] dp = new int[m + 1][n + 1];
for (int i = 1; i <= m; i++) {
    for (int j = 1; j <= n; j++) {
        if (text1.charAt(i-1) == text2.charAt(j-1)) {
            dp[i][j] = dp[i-1][j-1] + 1;    // 干净
        } else {
            dp[i][j] = Math.max(dp[i-1][j], dp[i][j-1]); // 干净
        }
    }
}

这个模式在哪都适用：

  • LCS / Edit Distance：dp[m+1][n+1]，dp[0][*]=dp[*][0]=0 代表空串对齐
  • 416 分割等和子集：dp[target+1]，dp[0]=true 代表空集和为 0
  • 322 零钱兑换：dp[amount+1]，dp[0]=0 代表凑 0 元需要 0 枚
  • 72 Edit Distance：dp[m+1][n+1]，首行首列分别代表对空串的操作
  • 300 LIS：dp[n] 已足够，dp[0]=1

通用原则：如果转移方程中依赖 dp[i-1] 或 dp[i][j-1]，多开一位让 base case 独立在 dp[0]，循环从 1 开始，就能消除所有边界 if 判断，让核心逻辑一目了然。

特征含义判断方式

✅ 适合 DP 的问题

  • 最值问题（最长、最短、最大、最小）
  • 计数问题（多少种方案）
  • 可行性判断（是否可达、是否可分割）
  • 递推关系明显的序列问题

✅ 不适合 DP 的问题

  • 求具体方案（路径、序列）→ 回溯更适合
  • 结果巨大但不需要模 → 指数爆炸
  • 子问题无重叠 → 用分治/贪心
  • 状态空间连续 → 用数学/二分

递归 vs 递推：两种 DP 实现方式

维度记忆化递归（Top-down）递推（Bottom-up）
方向从问题出发向下分解，到 base case 后返回从 base case 开始向上构建，直到目标
难点递归栈深度、缓存设计遍历顺序、边界初始化
代码递归 + memo 数组/Mapfor 循环填表
优势自然反映问题结构，只计算需要的子问题无递归开销，性能稳定
场景状态难以确定遍历顺序（区间DP常用）顺序已知（网格DP、一维DP）
面试中强烈推荐 Bottom-up，代码更简洁、性能更好、不易栈溢出。但区间DP（如 312 Burst Balloons）用记忆化递归更容易理解。
💡 效率取舍：Top-Down（记忆化递归）只计算递归路径上需要的子问题，如果某些状态永远不会被访问到，它自然跳过。但 Bottom-up 通常需要填满整个 dp 表，即使有些状态最终用不上也没办法跳过。因此当实际需要的子问题远小于状态空间时（例如某些状态根本不会出现），Top-Down 可能更快。
💡 什么时候需要填满、什么时候可以跳过？关键在于状态空间是否稠密 vs 稀疏：

需要填满整个 dp 表（稠密）：
  • 网格型（62 Unique Paths、64 Minimum Path Sum）— 每个格子都是可达的，填满就是最小计算量
  • 双序列型（1143 LCS、72 Edit Distance）— 二维表所有格子都需要参与计算，没有"无用的"子问题
  • 普通背包— dp 数组每个位置都可能被用到，填满就是最优复杂度
不需要 / 部分可跳过（稀疏）：
  • Coin Change（322）特例— 虽然 Bottom-up 填满了 dp[0..amount]，但其中真正能被硬币组合出来的只有一部分 dp[i] 会是非 -1。不过由于起点不确定，Bottom-up 无法预测哪些会成功，所以"全部都算"往往更简单。Top-Down 在硬币面值很大、amount 很大时（如 coins=[10000,20000], amount=10⁶）可以少走很多分支。
  • 区间 DP（312 Burst Balloons、877 Stone Game）— Bottom-up 按区间长度遍历，所有区间都要填；但 Top-Down 只探索递归路径上的区间。如果目标只有 dp[0][n-1]，且决策树中间剪枝很多，Top-Down 的实际计算量更小。
  • Word Break（139）— Bottom-up 从 0 填到 n，但一旦找到 dp[n] = true 就可以提前 break，不需要填完所有位置（早期终止优化）。
总结：面试首选 Bottom-up 写标准版，只有遇到状态空间极大且实际访问量远小于理论量（如超大 amount 的 Coin Change、复杂区间 DP）时才考虑 Top-Down。
💡 空间优化意识：二维 dp 很多时候可以压到一维（滚动数组），一维可以压到常数变量。先写出标准版再优化，不要一步到位。

二、无后效性详解（DP 最重要也最容易被忽略的特性）

无后效性（No Aftereffect / Markov Property）：一旦某个阶段的状态确定，后续决策只依赖于当前状态的值，不关心之前到达该状态的具体路径。"未来只关心现在是什么，不关心过去怎么来的"。

无后效性是 DP 区别于回溯/暴力搜索的核心分界线。有后效性的问题无法用简单的 dp 数组求解，但可以通过扩展状态维度将关键历史信息编码到状态中，从而消除后效性。

反例：有后效性的问题（含详细分析）

考虑一个网格路径问题：从左上角 (0,0) 走到右下角 (m-1,n-1)，只能向右或向下。但额外规则：不能连续两次向右（上一步向右了，这一步必须向下）。

// ❌ 有后效性的错误定义 — 直接套用标准网格DP
int[][] dp = new int[m][n];
dp[0][0] = 1;
for (int i = 0; i < m; i++)
    for (int j = 0; j < n; j++) {
        if (i > 0) dp[i][j] += dp[i-1][j]; // 从上往下
        if (j > 0) dp[i][j] += dp[i][j-1]; // 从左往右
    }
// 为什么错？
// dp[i][j-1] 包含了两种路径的计数：
//   ① 从上方到达 (i,j-1) 的路径（上一步是向下）
//   ② 从左方到达 (i,j-1) 的路径（上一步是向右）
// 从 (i,j-1) 向右走到 (i,j) 时，路径 ② 的最后一步是"向右"，
// 如果上一步已经是向右了，根据规则不能再向右，
// 所以路径 ② 不能继续向右！
// 但 dp[i][j-1] 只存了总数，无法区分①②。
// => 后效性：dp[i][j-1] 的值不足以决定"能否向右"这个未来
💡 有后效性的本质：当前状态丢失了未来决策所需的关键历史信息。上一步的方向决定了"能否继续向右"，但 dp[i][j] 只记录了路径总数，没有记录这个方向信息。不同路径走到同一个格子后，对未来的影响不同——这就是后效性。

修复：扩展状态维度消除后效性

// ✅ 将"上一步的方向"加入状态定义，消除后效性
// dp[i][j][0] = 从上方到达 (i,j) 的路径数（上一步是向下）
// dp[i][j][1] = 从左方到达 (i,j) 的路径数（上一步是向右）
// 这样每个状态对未来完全确定：
//   dp[i][j][0] → 下一步可右可下（从上往下，无连续向右限制）
//   dp[i][j][1] → 下一步只能向下（上一步已向右，不能再右）

int[][][] dp = new int[m][n][2];
dp[0][0][0] = 1; dp[0][0][1] = 1;

for (int i = 0; i < m; i++) {
    for (int j = 0; j < n; j++) {
        if (i == 0 && j == 0) continue;
        // 从上往下到 (i,j)：上一步无论怎么来都行
        if (i > 0) dp[i][j][0] = dp[i-1][j][0] + dp[i-1][j][1];
        // 从左往右到 (i,j)：上一步必须是从上往下来的
        // 关键：只用 dp[i][j-1][0]，不用 dp[i][j-1][1]
        // 因为 dp[i][j-1][1] 的最后一步是"向右"，不能连续向右
        if (j > 0) dp[i][j][1] = dp[i][j-1][0];
    }
}
// 结果 = dp[m-1][n-1][0] + dp[m-1][n-1][1]
// 现在每个状态只依赖确定的前驱，前驱的值不会因为"怎么来"而不同
// dp[i][j][0] → 只依赖 dp[i-1][j]，无循环依赖
// dp[i][j][1] → 只依赖 dp[i][j-1][0]，确定且唯一
// => 无后效性 ✓
扩展状态维度的本质：把"未来需要知道的过去信息"编码到当前状态中。加了"上一步方向"后，每个状态对未来的影响完全确定了，不再依赖更久远的历史。

LeetCode 实例：309 股票含冷冻期

如果只定义 dp[i] = 第 i 天的最大利润，是有后效性的——因为第 i 天能不能买入取决于第 i-1 天是否刚卖出（冷冻期），而 dp[i] 丢失了"最后一天是什么操作"这个信息。修复方案：扩展为三状态：

// 有后效性的错误定义
// dp[i] = 第 i 天的最大利润
// 问题：dp[i] 无法回答"今天能不能买入"（因为不知道昨天是否卖出）

// ✅ 扩展为三状态，消除后效性
// hold[i]  = 第 i 天结束时持有股票的最大利润
// sold[i]  = 第 i 天结束时刚卖出（明天冷冻）
// rest[i]  = 第 i 天结束时不持股且可买入

hold[i] = max(hold[i-1], rest[i-1] - prices[i])
sold[i] = hold[i-1] + prices[i]
rest[i] = max(rest[i-1], sold[i-1])
// 每个状态只依赖 i-1 天的状态，无后效性
💡 如何判断是否有后效性？问自己：从 dp[i] 的值只能知道"最优值是多少"，但不知道"达到这个最优值时的具体末态"，而未来决策需要这个末态信息吗？如果需要 → 有后效性。解法：扩展状态维度——把"达到 dp[i] 时的最后一个决策/状态"作为新维度加进去。

// House Robber 模板（一维DP典型结构）
public int rob(int[] nums) {
    if (nums.length == 0) return 0;
    if (nums.length == 1) return nums[0];
    int prev2 = nums[0];
    int prev1 = Math.max(nums[0], nums[1]);
    for (int i = 2; i < nums.length; i++) {
        int cur = Math.max(prev1, prev2 + nums[i]);
        prev2 = prev1;
        prev1 = cur;
    }
    return prev1;
}
// 空间 O(1)：只保留前两个状态，无需完整 dp 数组

// 以 64 Minimum Path Sum 为例：
public int minPathSum(int[][] grid) {
    int m = grid.length, n = grid[0].length;
    int[] dp = new int[n];
    dp[0] = grid[0][0];
    for (int j = 1; j < n; j++)
        dp[j] = dp[j-1] + grid[0][j];
    for (int i = 1; i < m; i++) {
        dp[0] += grid[i][0];
        for (int j = 1; j < n; j++)
            dp[j] = grid[i][j] + Math.min(dp[j], dp[j-1]);
    }
    return dp[n-1];
}
// 二维 O(mn) → 一维 O(n)，因为每行只依赖上一行和当前行左邻居

背包重点详解

一、倒序与正序（0-1 vs 完全）
0-1 背包每件物品只能用一次 → 更新时需要"没有当前物品"的旧状态 → 倒序。完全背包每件物品无限复用 → 更新时需要"已经放入过当前物品"的新状态 → 正序。

核心原理

  • 0-1 背包：每件物品只能用一次。更新当前容量时，需要用到没有放入当前物品时的净容量状态（即上一轮的老数据）。
  • 完全背包：每件物品可以无限次使用。更新当前容量时，需要用到已经放入过当前物品的容量状态（即这一轮的新数据）。

0-1 背包为什么倒序 — 以 416 为例

防止当前计算的值被本轮刚刚算出来的新值污染，必须用上一轮的"干净"旧值。

假设正在处理 num = 3，在此之前 dp[3] = false, dp[0] = true：

  • 正序计算：dp[3] = dp[3] || dp[0] = true（正确，3 没被用过）；dp[6] = dp[6] || dp[3] = true（错误，此 dp[3] 是本轮刚更新的，3 只能用一次，却被用了两次）
  • 倒序计算：dp[6] = dp[6] || dp[3] = false（dp[3] 还是旧值，还没算）；dp[3] = dp[3] || dp[0] = true（正确）

完全背包为什么正序 — 以 322 为例

由于硬币可以无限次使用，当我们计算 dp[j] 时，我们希望看到 dp[j - coin] 已经考虑过放入当前硬币后的情况了。正序保证了从小容量到大容量，前面算好的结果包含了已经使用过当前硬币的状态，从而实现无限复用。

💡 一句话总结：倒序 = 回头看旧版自己（0-1），正序 = 用新版自己继续叠（完全）。
二、组合 vs 排列（外层决定策略）
组合：外层物品，天然去重。排列：外层容量，每个位置尝试所有物品作为最后一步。

为什么组合要外层物品？

  • 外层遍历物品，相当于给所有组合加上一个硬性铁律：物品必须按照在数组中的先后顺序被放入背包。物品 1 一旦被讨论完，后面就再也没有机会把它放到物品 2 的后面去了。
  • 这样天然去重：[1, 2] 和 [2, 1] 永远不会同时出现。

为什么排列要外层容量 — 以 377 为例

  • 题目要求的是排列数（[1, 2] 和 [2, 1] 算两个不同答案）。
  • 当容量在外层时，我们一步步填满容量，对每一个固定容量都尝试最后一步放入哪一个物品。
  • 这意味着每次都可以从物品集合中任选一个作为最后一步，顺序不同的组合自然会被分别计数。
⚠️ 注意：当背包求最值（min/max）时，由于操作满足交换律，组合和排列的循环顺序不影响最终结果（如 322 Coin Change 用外物品内容量或外容量内物品都能得到正确答案）。只有计数问题才必须严格区分组合/排列的循环顺序。
⚠️ 494 Target Sum 的转化技巧：将数组分成 P（正号集）和 N（负号集），sum(P) - sum(N) = target，则 sum(P) = (total + target)/2。转化为：选若干元素使和为 (total+target)/2 的方案数 — 就是 0-1 背包计数。

416 的转化思路详解（0-1 背包的经典转化）

416 Partition Equal Subset Sum 是 0-1 背包可行性问题最经典的转化题。理解它的转化过程，就能举一反三处理大部分"分割"类问题。
💡 三个层次的理解

① 最基本的问题：给定数组，每个元素用一次，能否凑出 target？

// 最基本的 0-1 背包可行性问题
// nums = [1,2,3,5], target = 7 → 能否选出若干数（每个用一次）使其和为 7？
boolean[] dp = new boolean[target + 1];
dp[0] = true;
for (int num : nums) {
    // 每来一个 num：之前就能凑出 s？（跳过）或之前能凑出 s-num？（带上）
    for (int s = target; s >= num; s--) {    // 倒序 → 0-1（每个 num 只用一次）
        dp[s] = dp[s] || dp[s - num];        // 不取 || 取
    }                                        // 正序 → 完全（每个 num 无限复用）
}
return dp[target];

② 416 是什么？

给定数组，判断能否分成两个和相等的子集。例：nums = [1,5,11,5] → 可分成 [1,5,5] 和 [11]，和都是 11。

③ 416 的转化过程

  1. 问题等价变换：分成两个和相等的子集 → 找到一个子集，其和为 total/2（另一个子集自动就是剩下的数）
  2. 可行性判断：total 为奇数 → 直接 false；否则 target = total/2，就是基本问题
  3. 转化为 0-1 背包：每个数是一个物品，重量 = 数值，背包容量 = target，问能否恰好装满
🚫 常见错误：dp[s] = dp[x] || dp[s-x] 为什么不对？ 
// ❌ 错误直觉：枚举一个子集 x，看 x 和 s-x 是否都能凑出
boolean[] dp = new boolean[target + 1];
dp[0] = true;
for (int s = 1; s <= target; s++) {
    for (int x = 1; x < s; x++) {
        dp[s] = dp[x] && dp[s - x];  // ❌ 错误！
    }
}

两个致命问题：

  • 重复使用元素：dp[x] 和 dp[s-x] 可能用了同一个元素。例如 nums=[1,3,5], target=6，dp[1]=true 用了元素 1，dp[5] 可能也用了元素 1，但数组里只有一个 1。
  • 不是 DP 而是枚举：这种思路本质是在枚举分割点，dp[s] 依赖的子集组合可能完全不同。0-1 背包的"倒序遍历"才是正确的解法，它通过控制遍历顺序天然保证了每个元素只用一次。

总结：416 的转化就是 找子集和 = total/2，直接套用最基本的 0-1 背包可行性模板。核心思维是"将集合划分问题转化为子集和问题"，这个思路也适用于 494 Target Sum、2035 等题。

模式四：区间 DP（Interval DP）

dp[i][j] 表示区间 [i,j] 上的最优解。遍历顺序按区间长度从小到大，而不是按行列。
// 区间DP模板
int n = arr.length;
int[][] dp = new int[n][n];

// 初始化长度为1的区间
for (int i = 0; i < n; i++) dp[i][i] = baseValue;

// 按区间长度从小到大遍历
for (int len = 2; len <= n; len++) {
    for (int i = 0; i + len - 1 < n; i++) {
        int j = i + len - 1;
        // 枚举分割点 k
        for (int k = i; k < j; k++) {
            dp[i][j] = max/min(dp[i][j],
                               dp[i][k] + dp[k+1][j] + cost);
        }
    }
}

LIS（300）—— 两个版本都得会

✅ O(n²) DP 版

int[] dp = new int[n];
Arrays.fill(dp, 1);
int max = 1;
for (int i = 0; i < n; i++) {
    for (int j = 0; j < i; j++) {
        if (nums[j] < nums[i]) {
            dp[i] = Math.max(dp[i], dp[j] + 1);
        }
    }
    max = Math.max(max, dp[i]);
}
// dp[i] 以 i 结尾的 LIS 长度
// 必须依赖所有 j < i，所以 O(n²)

✅ O(nlogn) 耐心排序

int[] tails = new int[n];
int size = 0;
for (int num : nums) {
    int l = 0, r = size;
    while (l < r) {
        int m = l + (r - l) / 2;
        if (tails[m] < num) l = m + 1;
        else r = m;
    }
    tails[l] = num;
    if (l == size) size++;
}
// tails[i] 长度为 i+1 的 IS 的最小结尾
// 二分查找第一个 >= num 的位置替换它
// ⚠️ tails 不是 LIS 序列本身，只记录长度

int m = text1.length(), n = text2.length();
int[][] dp = new int[m+1][n+1];
for (int i = 1; i <= m; i++) {
    for (int j = 1; j <= n; j++) {
        if (text1.charAt(i-1) == text2.charAt(j-1))
            dp[i][j] = dp[i-1][j-1] + 1;
        else
            dp[i][j] = Math.max(dp[i-1][j], dp[i][j-1]);

}
// dp[i][j]：s1[0:i] 和 s2[0:j] 的 LCS 长度
// 相等时 +1，不等时取左/上最大值

public int maxSubArray(int[] nums) {

    int max = nums[0];

// 额外维护最小值（负负得正）

💡 为什么不用"以 i 结尾"定义？

对比两种定义方式：

  • "前 i 间"（当前写法）：dp[i] 存的是前 i 间的最优值，第 i 间可抢可不抢。转移时只需看相邻两间，O(1) 完成，答案在 dp[n-1]。
  • "以 i 结尾"（你提的）：dp[i] 存的是必须抢第 i 间的最大值。转移时要从 i-2 往前扫描最大值，O(n) 转移。即使优化到只看 dp[i-2] 和 dp[i-3]，公式也变成 nums[i] + Math.max(dp[i-2], dp[i-3])，且答案需遍历取 max。

根源：LIS/Kadane 用"以 i 结尾"是因为需要连续性（子序列、子数组必须包含最后一个元素才能延伸），定义自然要约束结尾。而 House Robber 的约束是"不能相邻"，这是全局约束，"前 i 间"的视角局部化解了它——每次只需在"跳过"和"抢"之间决策，无需回看。用"前 i 间"是更自然的选择。

    💡 为什么 w 升序、w 相等时 h 降序？

Maximum Product Subarray（152）⭐⭐⭐⭐

Kadane 变体，因为乘法符号翻转，需要同时维护最大和最小两个状态
💡 和 53 最大子数组和的本质区别：加法单调，乘法不单调。负数 × 负数 = 正数，所以"当前最小"可能变成"未来最大"。 
// 状态定义：
// curMax = 以当前元素结尾的**最大**乘积
// curMin = 以当前元素结尾的**最小**乘积

public int maxProduct(int[] nums) {
    int curMax = nums[0];
    int curMin = nums[0];
    int result = nums[0];

    for (int i = 1; i < nums.length; i++) {
        int num = nums[i];
        int prevMax = curMax;          // ⚠️ 必须暂存旧值！

        curMax = Math.max(num, Math.max(curMax * num, curMin * num));
        curMin = Math.min(num, Math.min(prevMax * num, curMin * num));

        result = Math.max(result, curMax);
    }
    return result;
}
// 三个候选来源：
// ① 从当前元素重新开始（nums[i]）
// ② 延续之前的最大乘积（max[i-1] * nums[i]）
// ③ 延续之前的最小乘积，符号翻转（min[i-1] * nums[i]）
⚠️ 必须暂存 prevMax：更新 curMin 需要旧 curMax（即 maxEnding[i-1]），如果先更新了 curMax，拿到的就是 maxEnding[i] 了。同理，更新 curMax 需要旧 curMin，好在 curMax 是第一个更新的，此时 curMin 还没变——所以只需要保存 prevMax。

152 在 DP 分类中属于 Kadane 变体：

  • 状态定义：以 i 结尾（而非"前 i 个"）
  • 答案位置：遍历取 max(curMax)（而非 dp[n]）
  • 特殊性：需要双状态（max + min），因为乘法打破了单调性

状态定义方式属于规律一中的"以 i 结尾"，答案需要从遍历中取最大值。具体见 Kadane 模式八中的对比代码。

五、常见错误

🚫 1. 背包问题循环顺序搞反 
// 错误 — 0-1 背包用了正序，导致同一物品被多次使用
for (int num : nums)
    for (int s = num; s <= target; s++)  // 正序 → 完全背包！
        dp[s] |= dp[s - num];

// 正确 — 0-1 背包用倒序
for (int num : nums)
    for (int s = target; s >= num; s--)  // 倒序 → 0-1 背包
        dp[s] |= dp[s - num];
🚫 2. 区间 DP 遍历顺序错误 
// 错误 — 按 i、j 递增遍历，依赖的状态还没算出来
for (int i = 0; i < n; i++)
    for (int j = i+1; j < n; j++)
        dp[i][j] = ... dp[i+1][j-1] ...;  // dp[i+1] 还没算！

// 正确 — 按区间长度从小到大
for (int len = 2; len <= n; len++)
    for (int i = 0; i + len - 1 < n; i++) {
        int j = i + len - 1;
        dp[i][j] = ...;
    }
🚫 3. Coin Change 初始值设成 Integer.MAX_VALUE 
// 错误 — dp[a-coin] + 1 会溢出成负数
int[] dp = new int[amount+1];
Arrays.fill(dp, Integer.MAX_VALUE);
dp[0] = 0;
// 当 dp[a-coin] == MAX_VALUE 时，+1 溢出成 Integer.MIN_VALUE
// Math.min 会选这个负数！

// 正确 — 用 amount+1 作为"不可能"标记
Arrays.fill(dp, amount + 1);
🚫 4. 子序列 vs 子数组（子串）混淆 
// 子序列：可以不连续 → 通常 dp 取 max（跳过）
// 子数组/子串：必须连续 → 不符合条件时 dp 归零

// 例：718 最长重复子数组（连续）
if (A[i-1] == B[j-1]) dp[i][j] = dp[i-1][j-1] + 1;
else dp[i][j] = 0;  // 不连续就断了！

// 而 1143 LCS（可以不连续）
if (A[i-1] == B[j-1]) dp[i][j] = dp[i-1][j-1] + 1;
else dp[i][j] = Math.max(dp[i-1][j], dp[i][j-1]);  // 跳过
🚫 5. 忘记检查"是否可达"（-1 / false 的情况） 
// 322 Coin Change：如果 amount 凑不出来，返回 -1
return dp[amount] > amount ? -1 : dp[amount];

// 139 Word Break：dp[0] = true；初始化不能漏
🚫 6. Decode Ways 忽略 '0' 的特殊处理 
// '0' 不能单独编码，只能和前一个数字组成 "10" 或 "20"
// 当 s[i-1] == '0' 时，dp[i] 不能从 dp[i-1] 转移
// 如果 s[0] == '0'，直接返回 0
🚫 7. 误以为 dp 数组越大越好——缺乏空间优化意识 
// 面试中可以先写标准二维/一维 DP，再提空间优化
// 很多题都可以从 O(n²) → O(n) → O(1)
// 但不要一开始就写滚动数组，容易搞混边界
// 策略：先 AC 标准版，再说"还可以优化到 O(1)"

六、结论

DP 的难点不是代码，而是状态定义。定义对了，转移方程自然浮现。

DP 经验公式（状态定义规律总结）

规律一：一维 DP 的三种状态定义

定义方式适用场景典型题答案位置
dp[i] = 以 i 结尾的某个定义 子序列 / 子数组问题（必须包含最后一个元素） 300 LIS、53 最大子数组和、152 乘积子数组、5 回文子串 max(dp[0..n-1])
dp[i] = 前 i 个（0..i-1）的某个定义 递推累加问题（不要求以 i 结尾，只关心前 i 个的整体） 70 爬楼梯、198 打家劫舍、139 单词拆分、91 解码方法 dp[n]
dp[a] = 凑成值 a 的某个定义 背包 / 凑数问题（容量作为状态） 322 零钱兑换、416 分割等和、518 零钱兑换II dp[amount] 或 dp[target]
判断口诀：需要"结尾信息" → 以 i 结尾；只关心"整体结果" → 前 i 个；有"容量限制" → 以容量为状态。

规律二：二维 DP 的四种状态定义

定义方式适用场景典型题答案位置
dp[i][j] = 数组A前 i 个、数组B前 j 个的某个定义 两个序列比较（LCS、编辑距离、正则匹配） 1143 LCS、72 编辑距离、10 正则匹配、97 交错字符串、115 不同子序列 dp[m][n]
dp[i][j] = 到达网格位置 (i,j) 的某个定义 网格路径问题（从起点到终点） 62 不同路径、64 最小路径和、221 最大正方形 dp[m-1][n-1] 或遍历取 max
dp[i][j] = 区间 [i,j] 上的某个定义 区间问题（回文、合并、博弈） 5 最长回文子串、516 最长回文子序列、312 戳气球、877 石子游戏 dp[0][n-1]
dp[i][j] = A以 i 结尾、B以 j 结尾的某个定义 连续匹配问题（必须同时以 i,j 结尾） 718 最长重复子数组 遍历取 max(dp[i][j])

规律三：两个序列问题时，dp[i][j] 的最常见定义

绝大多数两个字符串/数组的 DP 题，dp[i][j] 定义为 「A[0:i] 和 B[0:j]」（前 i 个和前 j 个），答案在 dp[m][n]。

例外情况：当要求连续匹配时（如 718 最长重复子数组），dp[i][j] 定义为"以 A[i] 和 B[j] 结尾"，答案需要遍历取 max。

规律四：返回值的位置

状态定义答案位置原因
以 i 结尾max(dp[0..n-1])不知道最优解在哪个位置结尾
前 i 个 / 前 i 个和 j 个dp[n] 或 dp[m][n]自然收敛到完整输入
区间 [i,j]dp[0][n-1]自然收敛到完整区间
到达 (i,j)dp[m-1][n-1]自然收敛到终点

状态机（股票类）某状态变量的值结束时刻指定状态的值

规律五：子序列 vs 子数组（连续 vs 不连续）的影响

子序列（不要求连续）子数组/子串（必须连续）
dp[i] 定义以 i 结尾的子序列以 i 结尾的子数组
不匹配时dp[i] = dp[i-1]（继承前一个）dp[i] = 0 或 dp[i] = nums[i]（重新开始）
二维不匹配时max(dp[i-1][j], dp[i][j-1])（跳过）dp[i][j] = 0（断开）

总结：写 DP 的第一步是问自己三个问题——① 几维？② 状态表示"以 i 结尾"还是"前 i 个"？③ 最终答案在哪？90% 的 DP 题的答案都在这三个问题的框架内。
每个模式学透后，同一模式的新题就是微调转移方程——这是 DP 复习最高效的策略。
