Sliding Window (滑动窗口)

核心性质：滑动窗口适用于连续子串/子数组问题，通过左右指针维护窗口来在线性时间内求解。核心在于明确窗口的扩张条件、收缩条件和答案更新时机。

几类题型

  • 固定窗口 — 窗口大小固定，滑动过程中更新答案
  • 最大窗口 — 最长满足条件的子串/子数组，窗口不满足约束时收缩
  • 最小窗口 — 最短满足条件的子串/子数组，窗口满足目标时尽量收缩

最大窗口通用模版

int left = 0;
int answer = 0;
for (int right = 0; right < n; right++) {
    // 1. 扩张窗口：加入 nums[right] / s.charAt(right)
    add(right);
    // 2. 如果窗口不满足约束，持续收缩
    while (windowIsInvalid()) {
        remove(left);
        left++;
    }
    // 3. 此时 [left, right] 是一个合法窗口
    answer = Math.max(answer, right - left + 1);
}
return answer;

最小窗口通用模版

int left = 0;
int answer = Integer.MAX_VALUE;
for (int right = 0; right < n; right++) {
    // 1. 扩张窗口
    add(right);
    // 2. 一旦窗口满足目标，尽量收缩
    while (windowIsValid()) {
        answer = Math.min(answer, right - left + 1);
        remove(left);
        left++;
    }
}
return answer == Integer.MAX_VALUE ? 0 : answer;

举例

主要是不同题型的状态怎么维护，怎么快速判断不满足或者满足。

  • LeetCode 3 — 无重复字符最长子串
    • count[128] 为状态，因为只有 char。
  • 最多包含 K 个不同字符的最长子串
    • Map 为状态，因为需要存频次。K 取任意常数可复用。
    • LeetCode 904 就是 K=2 的特例。
  • LeetCode 209 — Minimum Size Subarray Sum
    • sum 为状态。
  • LeetCode 76 — Minimum Window Substring
    • 难点在于：不能每次都遍历整个 Map 来判断窗口是否合法。
    • t 需要什么字符、每个字符需要多少个。
    • 如何快速判断 windowIsValid? — formed + required 字段的引入，使得 O(1) 能回答这个问题。

    • 桶排序思想维护窗口内元素的近似性。
