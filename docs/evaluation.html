表达式求值：± vs ±*/ 控制流对比

核心洞见：运算符的数量决定了"延迟结算"的程度。±只有一级优先级，立即结算；±*/ 有二级优先级，需要缓冲一个局部块。

1. 两种版本对比

版本 A：只有 ±

特征：遇到 +/- 直接结算当前数字，操作是即时且无状态的。 
// 等号两边是对称的：一边是 + 和 - 的 if-else
while (i < s.length()) {
    if (Character.isDigit(s.charAt(i))) {
        num = num * 10 + s.charAt(i) - '0';
    } else {                              ← 单一的 else 分支处理所有非数字
        curResult = curResult + sign * num;     ← 立即释放
        sign = s.charAt(i) == '+' ? 1 : -1;    ← 更新符号
        num = 0;
    }
    i++;
}
curResult += sign * num;                       ← 末尾还有一段

版本 B：± \*/

特征：数字和运算符在两个独立的 if 中（非 else if），运算符触发结算的是上一个运算符的积累。 
// 这里是不对称的：数字的 if 和 运算符的 if 是并行的
for (int i = 0; i < len; i++) {
    char ch = s.charAt(i);

    // if 1：攒数字
    if (Character.isDigit(ch)) {
        num = num * 10 + (ch - '0');
    }

    // if 2：遇到运算符/结尾 → 结算上一段
    // 注意：这不是 else if！两个 if 独立！
    if (sign == '+' || sign == '-' || sign == '*' || sign == '/' || i == len - 1) {
        if (sign == '+') {
            res += lastNum;
            lastNum = num;
        } else if (sign == '-') {
            res += lastNum;
            lastNum = -num;
        } else if (sign == '*') {
            lastNum = lastNum * num;
        } else if (sign == '/') {
            lastNum = lastNum / num;
        }
        sign = ch;     ← sign 更新为当前字符 ch，而 c 只是触发时刻
        num = 0;
    }
}
res += lastNum;                              ← 末尾还有一段

2. 好记的口诀："运算符不是对当前 operator 做事，而是对上一个"

完整的控制流逻辑：

  1. 攒数字：num = num * 10 + digit
  2. 一旦碰到运算符或结尾，就用 prevOp（即 sign）结算 num，然后 sign = ch
  3. 数字和结算必须在两个独立的 if 中，否则文件 / 字符串结束时最后一段数字算不进去

2.1 为什么不能用 else if？

看最后一个字符的情况：假设表达式是 "1+2*3"，字符串以 '3' 结尾。

  • 遍历到最后 i=4，ch='3'
  • 如果是 else if，ch='3' 是数字 → 走数字分支，攒 num=3
  • 循环结束 → 3 没有触发结算，丢失了

所以结算的触发条件 if (sign == ... || i == len - 1) 必须是独立的 if，用 else if 就会漏掉结尾的数字。

3. 两张图：控制流对比

± only —— "if 是动作触发器，else fall through 无副作用"

循环开始
  │
  ├─ 如果 c 是数字 → num = num * 10 + digit
  │
  └─ else → curResult += sign * num     ← 立即释放当前数字
             sign = (c == '+') ? 1 : -1  ← 更新符号
             num = 0
  │
循环结束 → curResult += sign * num      ← 最后一段

± \*/ —— "运算符是终态的触发器"

循环开始
  │
  ├─ 如果 c 是数字 → num = num * 10 + digit
  │
  ├─ 如果 c 是运算符 或 结尾 → 用 prevOp 结算 num   ← NOT c，是 prevOp！
  │   │
  │   ├─ prevOp = '+' → res += lastNum; lastNum = num
  │   ├─ prevOp = '-' → res += lastNum; lastNum = -num
  │   ├─ prevOp = '*' → lastNum = lastNum * num
  │   └─ prevOp = '/' → lastNum = lastNum / num
  │
  │   prevOp = c     ← 把 c 记住，留给下一轮用
  │   num = 0
  │
循环结束 → res += lastNum                ← 最后一段
一句话总结版本 B：运算符 c 是结算上一个 prevOp 的扳机，然后 c 成为新的 prevOp。
