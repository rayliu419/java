排序思想总结

核心思路：排序不仅仅是把数组排好序，更是利用"有序"这个条件来简化问题。Partition 思想找第 K 大、归并排序算逆序对、桶排序利用鸽巢原理跳过比较——理解排序算法的本质，才能在算法题中灵活运用。

1. QuickSort 的 Partition 思想

QuickSort 的 partition 将一个数组分成两部分：左区 ≤ pivot，右区 ≥ pivot。这个操作能确定 pivot 在全局排序中的最终位置，由此衍生出 QuickSelect 算法——找第 K 大/小元素的核心工具。

核心心法：Partition 不关心左右的顺序，只关心"哪些元素在 pivot 左边、哪些在右边"。这种"只比一半"的特性使得时间复杂度从排序的 O(n log n) 降为 O(n)。 
// 标准分区：pivot 选最后一个元素
int partition(int[] nums, int lo, int hi) {
    int pivot = nums[hi];
    int i = lo;  // i 指向"下一个 < pivot 的元素的位置"
    for (int j = lo; j < hi; j++) {
        if (nums[j] < pivot) {
            swap(nums, i, j);
            i++;
        }
    }
    swap(nums, i, hi);  // pivot 归位
    return i;           // 返回 pivot 最终位置
}

// QuickSelect：找第 K 小
int quickSelect(int[] nums, int lo, int hi, int k) {
    int p = partition(nums, lo, hi);
    int rank = p - lo + 1;  // pivot 在区段内的排名（第几小）
    if (rank == k)      return nums[p];
    else if (k < rank)  return quickSelect(nums, lo, p - 1, k);
    else                return quickSelect(nums, p + 1, hi, k - rank);
}
方法时间复杂度空间复杂度说明
排序取第 KO(n log n)O(1)最简单，但慢
QuickSelect（期望）O(n)O(log n) 递归栈原地修改，期望线性时间
最小堆（第 K 大）O(n log k)O(k)适合数据流 / k 较小时
注意：QuickSelect 最坏情况 O(n²)（每次 pivot 都是最值）。实战中用随机选 pivot 或"三数取中"来避免退化。

2. Merge Sort 计算逆序数

逆序对（Inversion）定义：若 i < j 且 a[i] > a[j]，则 (i, j) 为一个逆序对。逆序数衡量数组的"无序程度"——完全有序为 0，完全逆序为最大值 n(n-1)/2。

核心心法：归并排序在合并两个有序子数组时，可以"顺手"统计跨越左右两部分的逆序对，且归并排序不会破坏数组的相对顺序，保证每个逆序对恰好被统计一次。 
int mergeSort(int[] nums, int l, int r) {
    if (l >= r) return 0;
    int mid = l + (r - l) / 2;
    int inv = mergeSort(nums, l, mid) + mergeSort(nums, mid + 1, r);
    // 合并时统计跨越左右两部分的逆序对
    int[] tmp = new int[r - l + 1];
    int i = l, j = mid + 1, k = 0;
    while (i <= mid && j <= r) {
        if (nums[i] <= nums[j]) {
            tmp[k++] = nums[i++];
        } else {
            // nums[i..mid] 都比 nums[j] 大（两个子数组各自有序）
            inv += mid - i + 1;  // 关键：一次统计多个逆序对
            tmp[k++] = nums[j++];
        }
    }
    while (i <= mid) tmp[k++] = nums[i++];
    while (j <= r)   tmp[k++] = nums[j++];
    System.arraycopy(tmp, 0, nums, l, tmp.length);
    return inv;
}

为什么合并时能一次统计多个逆序对？

合并时，左右两个子数组各自 已经有序。当 nums[i] > nums[j] 时，由于左子数组是升序的，nums[i..mid] 全部大于 nums[j]。因此一次性加 (mid - i + 1)，而不是逐个比较。

方案时间复杂度空间复杂度说明
暴力双层循环O(n²)O(1)n 大时不可用
归并排序法O(n log n)O(n)最优解法，修改原始数组
Fenwick 树 / BITO(n log n)O(n)不修改原数组，需要值域压缩
提示：如果要求不修改原数组，可以在归并前复制一份临时数组，每次比较在原数组上操作。而 BIT 解法天然不修改原数组，适合需要保留原始数据的场景。

3. Bucket Sort 与 Maximum Gap

Maximum Gap 问题（LeetCode 164）：给定无序数组，求排序后相邻元素的最大差值。要求 O(n) 时间和空间。

直接排序是 O(n log n)，桶排序可以做到 O(n)。关键在于利用鸽巢原理（Pigeonhole Principle）跳过桶内比较：

// 1. 找 min 和 max
int min = Arrays.stream(nums).min().getAsInt();
int max = Arrays.stream(nums).max().getAsInt();

// 2. 计算桶大小和桶数
int n = nums.length;
if (n < 2) return 0;
// 关键：桶的大小恰好是平均间距的"下限"
int gap = Math.max(1, (max - min) / (n - 1));
int bucketCount = (max - min) / gap + 1;

// 3. 每个桶只记录 min 和 max（不需要记录所有元素）
int[] bucketMin = new int[bucketCount];
int[] bucketMax = new int[bucketCount];
Arrays.fill(bucketMin, Integer.MAX_VALUE);
Arrays.fill(bucketMax, Integer.MIN_VALUE);

for (int v : nums) {
    int idx = (v - min) / gap;
    bucketMin[idx] = Math.min(bucketMin[idx], v);
    bucketMax[idx] = Math.max(bucketMax[idx], v);
}

// 4. 遍历桶，计算 gap
int maxGap = 0;
int prevMax = min;
for (int i = 0; i < bucketCount; i++) {
    if (bucketMin[i] == Integer.MAX_VALUE) continue; // 空桶
    // gap 一定出现在前一个桶的 max 和当前桶的 min 之间
    maxGap = Math.max(maxGap, bucketMin[i] - prevMax);
    prevMax = bucketMax[i];
}
核心心法——为什么不需要桶内排序？
  1. 桶数 = n - 1，n - 2 个元素（去掉 min, max）分配到 n - 1 个桶中 → 至少有一个空桶
  2. 空桶左右两端的最小差至少为 gap，所以 最大 gap 不可能出现在桶内，只可能跨桶
  3. 因此只需记录每个桶的 min 和 max，相邻非空桶的 bucketMin[i] - prevMax 就是候选 gap
易错点：当 min == max 时（所有元素相同），gap = 0，bucketCount = 1。此时只有一个桶，直接返回 0。另外注意整数除法向下取整可能导致 gap = 0，需要用 Math.max(1, ...) 保护。

4. K 距离偏移排序

问题描述：给定一个数组，每个元素距离其排序后的正确位置 不超过 k。在 O(n log k) 时间内将其排序。

核心心法：每个元素只可能在正确位置前后 k 个位置的范围内，所以用大小为 (k+1) 的最小堆，滑动窗口式地处理——堆中始终维护"当前及后面 k 个元素"的最小值。 
// 滑动窗口 + 最小堆，O(n log k)
void sortNearlySorted(int[] nums, int k) {
    int n = nums.length;
    // 1. 建堆：大小为 k+1（因为下标 i 的元素可能跳到 i+k 的位置）
    PriorityQueue<Integer> minHeap = new PriorityQueue<>(k + 1);
    for (int i = 0; i <= Math.min(k, n - 1); i++) {
        minHeap.offer(nums[i]);
    }
    // 2. 滑动窗口：弹出当前最小值，推入下一个新元素
    int idx = 0;
    for (int i = k + 1; i < n; i++) {
        nums[idx++] = minHeap.poll();
        minHeap.offer(nums[i]);
    }
    // 3. 清空堆中剩余元素
    while (!minHeap.isEmpty()) {
        nums[idx++] = minHeap.poll();
    }
}

正确性证明思路：

  1. 元素 a[i] 的正确位置是 [i-k, i+k] 范围内
  2. 当我们需要确定位置 0 的元素时，由于 0 位置的元素必然来自下标 [0, k] 范围，堆中包含了这些候选，堆顶就是全局最小值
  3. 以此类推，窗口每滑动一格，堆中始终包含了"当前格及其后 k 个"的所有候选元素
解法时间复杂度空间复杂度说明
直接排序O(n log n)O(1)没利用"k 距离"的条件
插入排序O(n · k)O(1)内循环最多执行 k 次，k 小时可用
最小堆滑动窗口O(n log k)O(k)k 较大时的最优解

总结：
  • 找第 K 大/小 → QuickSelect（partition 思想），平均 O(n)
  • 计数逆序对 → MergeSort 合并阶段顺手统计，O(n log n)
  • Maximum Gap → Bucket Sort + 鸽巢原理跳过桶内比较，O(n)
  • K 距离排序 → 大小为 k+1 的最小堆滑动窗口，O(n log k)
  • 这三种场景的核心共同点：不追求完整排序，而是利用排序过程的部分信息解决问题
