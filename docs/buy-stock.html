股票买卖系列（状态机 DP）

股票系列的核心矛盾是后效性：当前决策（买/卖）的可行性依赖于过去操作留下的"痕迹"（是否持股、交易了几次、是否刚卖完）。DP 通过把痕迹编码到状态中来解决后效性。 不同题目的差异，只是"痕迹"的内容不同。

buy stock I — 121. Best Time to Buy and Sell Stock

整个过程只能买一次。后效性不存在，一个变量就够了。

  • 因为只能买一次，不需要知道任何历史状态，只需要知道历史最低价。
int minPrice = Integer.MAX_VALUE;
int maxProfit = 0;
for (int price : prices) {
    if (price < minPrice)
        minPrice = price;
    else if (price - minPrice > maxProfit)
        maxProfit = price - minPrice;
}
return maxProfit;

本质：问题退化为「在历史最低点买入，在未来最高点卖出」。不需要 DP。

buy stock II — 122. Best Time to Buy and Sell Stock II

无限次交易，但手中只能持有 1 支股票。

后效性分析

buy stock II 会破坏无后效性：即使当前价格适合买入，能否买入取决于手里是否有股票。如果只用一维 dp[i]（第 i 天的最大利润），就无法区分"手里有股"和"手里无股"这两种状态——它们对未来（能否买入）的影响完全不同。

解决：扩展为二维 DP，把"持股状态"显式编码到状态中。

DP 解法

定义

  • dp[i][0]：第 i 天结束时，不持有股票的最大利润。
  • dp[i][1]：第 i 天结束时，持有股票的最大利润。

递推公式

dp[i][0] = max(dp[i-1][0], dp[i-1][1] + prices[i])   // 继续空仓 / 卖出
dp[i][1] = max(dp[i-1][1], dp[i-1][0] - prices[i])   // 继续持有 / 买入

初始化

dp[0][0] = 0;
dp[0][1] = -prices[0];

结果：dp[n-1][0]

空间优化：i 的结果只依赖 i-1，用 cash（不持股）和 hold（持股）两个变量滚动：

int cash = 0, hold = -prices[0];
for (int p : prices) {
    cash = Math.max(cash, hold + p);
    hold = Math.max(hold, cash - p);
}
return cash;

为什么贪心法也能解？

无限次交易意味着可以把一次长持有拆成多段短持有，总和不变：

  • 例如 [1,3,5]：1买5卖=4；1买3卖(2) + 3买5卖(2)=4 → 一样
  • 所以只要价格今天比昨天高，就当作昨天买今天卖，累加这个差价。
  • 累加正差价是 DP 在 k=∞ 时的退化特例，因为不需要考虑持股状态以外的历史信息了。
int profit = 0;
for (int i = 1; i < prices.length; i++) {
    if (prices[i] > prices[i - 1])
        profit += prices[i] - prices[i - 1];
}
return profit;

buy stock IV — 188. Best Time to Buy and Sell Stock IV

最多只能交易 K 次，手中只有一只股票。III 是特例 K=2。

后效性分析

贪心算法彻底失效了——不能一看到有利润就交易。如果整个大盘有三次暴涨机会，你必须放弃其中涨幅最小的那一次，选择能带来最大利润的两次。

这里的"痕迹"有两个：

  1. 是否持股（和 II 一样）
  2. 已经交易了多少次（新的后效性来源）

只有持股状态还不够——即使知道手里没股票，也无法判断还能不能继续交易。所以需要把"当前是第几次交易"也编码到状态中。

解决：引入第三个维度 K，表示已经完成的交易次数（买入算作一笔交易的开始）。

DP 定义

  • dp[i][k][0]：第 i 天结束时，已经进行了 k 次交易，且当前不持有股票。
  • dp[i][k][1]：第 i 天结束时，已经进行了 k 次交易，且当前持有股票。

递推公式

dp[i][k][0] = max(dp[i-1][k][0], dp[i-1][k][1] + prices[i])   // 继续空仓 / 卖出（完成第k笔）
dp[i][k][1] = max(dp[i-1][k][1], dp[i-1][k-1][0] - prices[i]) // 继续持有 / 买入（开启第k笔）

关键理解：买入时 k 增加（标志着新交易的开始），所以从 k-1 转移过来；卖出时 k 不变（只是完成了已经在进行的第 k 笔交易）。

初始化

  • dp[0][1][0] = 0：第 0 天不持股，属于第 1 次交易，利润 0
  • dp[0][1][1] = -prices[0]：第 0 天买入，开启第 1 次交易
  • dp[0][2][0] = -∞：第 0 天不可能完成第 2 次交易
  • dp[0][2][1] = -prices[0]：第 0 天直接买入强行开启第 2 次交易（设为 -∞ 也可，-prices[0] 能保证后续转移正确）

关于 dp[i][1][0] 的常见误解

  • k=1, status=1：第 1 次买入，还没卖（进行中）
  • k=1, status=0：第 1 次买入并已卖出（已结束）
  • dp[i][1][0] 是 第一笔已经结束，不是"第一笔还没开始"。「还没开始」对应的是 dp[i][0][0]（k=0，没买过）。

K=2 时的四变量手写优化

K=2 时每天只有 4 种具体状态流动，可以拍平为 4 个变量：

int buy1 = -prices[0], sell1 = 0;
int buy2 = -prices[0], sell2 = 0;
for (int p : prices) {
    buy1  = Math.max(buy1, -p);
    sell1 = Math.max(sell1, buy1 + p);
    buy2  = Math.max(buy2, sell1 - p);
    sell2 = Math.max(sell2, buy2 + p);
}
return sell2;

五状态含义：rest / 持有1 / 空仓1 / 持有2 / 空仓2

当 K > n/2 时的退化

如果 K > n/2，问题退化为 buy stock II（无限次交易），因为每天买卖一次最多也只能做 n/2 次交易。此时 K 不再是约束，不需要三维 DP。

buy stock V — 309. Best Time to Buy and Sell Stock with Cooldown

无限次交易，但卖出后第二天不能买入（冷冻期 1 天）。

后效性分析

为什么两状态 DP（cash/hold）不够？因为第 i 天能不能买入取决于第 i-1 天是否刚卖出。hold 状态丢失了"昨天是否卖过"这个信息——这是新的后效性来源。

解决：将"不持股"拆为两个状态：sold（刚卖出，明天冷冻）和 rest（不持股且可买入）。

三状态 DP

int hold = -prices[0];  // 持有股票
int sold = 0;            // 刚卖出（明天冷冻）
int rest = 0;            // 不持股且可买入

for (int p : prices) {
    int prevSold = sold;
    sold = hold + p;                 // 卖出：hold → sold
    hold = Math.max(hold, rest - p); // 买入：rest → hold（不能从 sold 买入）
    rest = Math.max(rest, prevSold); // 冷冻恢复：sold → rest
}
return Math.max(sold, rest);

状态机转移：

rest ←→ hold  (买入：rest → hold)
hold → sold   (卖出：hold → sold)
sold → rest   (冷冻恢复：sold → rest)

关键：hold 只能从 rest 转移，不能从 sold 转移——卖出的第二天不能买入。

buy stock VI — 714. Best Time to Buy and Sell Stock with Transaction Fee

无限次交易，但每次卖出需要支付手续费 fee。

与 buy stock II 几乎完全一样，后效性来源相同（只需知道是否持股），只是卖出时扣手续费：

int cash = 0, hold = -prices[0];
for (int p : prices) {
    cash = Math.max(cash, hold + p - fee);  // 卖出时扣手续费
    hold = Math.max(hold, cash - p);
}
return cash;

注意：有手续费时不能再用贪心法（累加正差价）。因为每次交易有固定成本，必须权衡是否值得交易——这正是 DP 的优势，它能全局最优地决定要不要交易。

后效性与状态扩展的对应关系

后效性来源表现解法对应题目
不知道手里是否有股票当前能否买入不确定加 status 维度（持股/不持股）122
不知道已经交易了几次是否还能继续交易不确定加 k 维度（交易次数）123, 188
不知道是否处于冷冻期今天能否买入不确定拆分"不持股"为 sold/rest309
手续费交易是否需要扣钱转移方程直接减 fee（无需加维度）714

本质：把"未来需要知道的过去信息"编码到当前状态中。 每个新约束引入一个新的后效性来源，对应地在状态空间中增加一个维度。状态扩展后，每个状态的转移只依赖昨天相邻状态，不再依赖更久远的历史，后效性被消除。
