学习笔记

一、核心心法

二分查找的每一轮循环开始前，我们都确信答案一定在 [low, high] 范围内（如果存在的话）。这个确信的结论就是"不变量"。根据 mid 与 target 的比较结果，我们缩小区间，同时保证这个不变量仍然成立。当区间缩小到空集（或只剩一个元素）时，答案就找到了。

完整决策流程

mid 有可能是答案吗？
├─ 否 → 排除：low = mid+1 / high = mid-1
│    ├─ 循环条件：区间能缩到空 → 用 <=
│    └─ 取整：无所谓 → 惯例下取整
└─ 是 → 两种处理方式：
     ├─ 保留式：答案留在区间内，low = mid / high = mid
     │    ├─ 循环条件：区间缩不到空 → 必须用 <（退出时 low==high 即答案）
     │    └─ 取整：mid 不能等于被保留的端点
     │         ├─ high = mid → 下取整（mid 偏左）
     │         └─ low = mid  → 上取整（mid 偏右）
     └─ 记录式：答案搬到 ans 里，区间照常排除 ±1
          ├─ 循环条件：区间能缩到空 → 必须用 <=（退出时答案 = ans）
          └─ 取整：无所谓 → 惯例下取整

概览

  • 什么时候用二分？ 只要数据是有序的，或者局部有序的，就应该适当考虑二分查找的方法。
  • 猜数法：需要猜数或者用不同的数来试某个解时，使用二分法快速试错。

三、实现细节

如何写出 bug free 的二分

二分查找最大的问题是很难写出 bug free 的代码，策略：用 test case 驱动，很难直接思考。

边界条件单独处理：

  • low 或 high 从未被重置过的情况。这种可能能被后面统一处理，如果比较复杂，就单独拉出来讨论。
  • 剩下的就是 low 和 high 都被重置过的。

插入位置 test case：

  • 奇数数组：[1, 3, 5] 插入 2；[1, 3, 5] 插入 4。
  • 偶数数组：[1, 3, 5, 7] 插入 2；[1, 3, 5, 7] 插入 4。

ans 变量的使用

变体题设置一个 ans 变量，记录最后 break 出循环的解，因为可能 break 出去以后，下次就找不到更好的解了。

某些情况下，break 出去还得检查最后的 low 是不是解。 变体中，最后的解是在循环中 ans 的解和 low 的解中的一个。

四、各题要点

Binary Search（704）⭐⭐⭐⭐⭐

  • 最基础的二分模板，建议一次性写对
  • 终止条件 low <= high，每次更新 mid ± 1

Search Insert Position（35）⭐⭐⭐⭐⭐

  • 等价于 lower_bound：找第一个 ≥ target 的下标
  • 如果所有数都 < target，返回 nums.length
  • 可以直接用左边界写法，最终返回 low：
int searchInsert(int[] nums, int target) {
    int low = 0, high = nums.length - 1;
    while (low <= high) {
        int mid = low + (high - low) / 2;
        if (nums[mid] >= target)  high = mid - 1;
        else                      low = mid + 1;
    }
    return low;
}

Find First and Last Position（34）⭐⭐⭐⭐⭐

  • 左右边界分解成两个独立函数，各调一次
  • 左边界：nums[mid] >= target → high = mid - 1，记录 ans
  • 右边界：nums[mid] <= target → low = mid + 1，记录 ans
  • 不存在时返回 [-1, -1]

Sqrt(x)（69）⭐⭐⭐⭐⭐

看似简单的二分，但极容易写错。因为 mid² ≤ x 时 mid 本身可能就是最终答案，但你往往会在 low = mid + 1 时把它跳过去。这道题是验证自己对二分「不变量」理解深度的试金石。

✅ 正确写法

int mySqrt(int x) {
    if (x < 2) return x;
    int low = 1, high = x / 2;
    int ans = -1;
    while (low <= high) {
        int mid = low + (high - low) / 2;
        if (mid < x / mid) {          // mid² < x
            ans = mid;                 // 记录候选
            low = mid + 1;             // 尝试更大的
        } else if (mid > x / mid) {
            high = mid - 1;
        } else {
            return mid;                // 精确匹配
        }
    }
    return ans;
}

要点：用 ans 变量记录最后一个可行的 mid，循环条件用 <=。

逐版 bug 分析

版本代码Bug失败例子
V1 mid * mid 直接相乘 整数溢出，mid * mid 变成负数 x = Integer.MAX_VALUE
V2 while (low < high) + ans 变量 low == high 时循环不进，可能跳过唯一的解 x = 2

核心教训

  • 数值二分的溢出陷阱：永远用 mid > x / mid 代替 mid * mid > x
  • mid² < x 时 mid 可能是最终答案 → 可以 low = mid + 1 排除（记录式），但必须同时 ans = mid 记录，不能只 +1 不记录
  • 带 ans 变量的写法必须用 while (low <= high)，否则 low == high 时的解会被漏掉
  • 二分范围可以优化为 [1, x/2]（除 0、1 外），因为 √x ≤ x/2 对所有 x ≥ 4 成立

Search in Rotated Sorted Array（33）⭐⭐⭐⭐

核心设计思维：从「无序」中找「有序」，利用有序判定方向。

旋转数组有一个关键性质：从中点一切，至少有一半是有序的。这个性质是必然成立的不变量——nums[low..mid] 和 nums[mid..high] 不可能同时无序。

算法思路

不变量：每一轮二分，总能找到一个完全有序的区间。

基于这个有序区间，做标准二分判断——检查 target 是否落在它的值域内：

if (左边有序) {
    if (target 在 [nums[low], nums[mid]) 范围内) → 缩到左边
    else → 去右边
} else {
    // 右边一定有序
    if (target 在 (nums[mid], nums[high]] 范围内) → 缩到右边
    else → 去左边
}

为什么这么设计是正确且完备的

普通二分的核心前提是「数组整体有序」，但旋转数组整体无序。所以不能直接用 nums[mid] > target 来决定方向。

这个算法的核心是把问题做了归约：从整体无序中找到一个局部有序区间，在这个区间上应用标准二分的判定逻辑。目标要么在这个有序区间里（直接用大小比较判定），要么在另一半——而另一半被排除后，剩下的子数组仍然是旋转数组（只是规模更小），"至少半边有序"这个性质递归成立。

这个过程之所以成立，依赖的是排中律：

  • if 分支：检查 target 是否在已知有序的半边——纯数学的区间包含关系，一次 O(1) 的大小比较即可判定，没有歧义
  • else 分支：target 不在有序的半边 → 那只能在另一半（哪怕它无序）。这不需要额外的判断，而是逻辑推导的结果

算法在每一轮只做一件简单确定的事——利用已知的有序区间做判定，而把看似复杂的情况交给「取反后递归」。这是一个典型的「复杂问题 → 拆解出可计算的局部 → 其余部分递归处理」的思维模式。

边界条件：nums[low] == nums[mid]

如果用 nums[low] <= nums[mid] 来判断左半边有序（而非 <），当 nums[low] == nums[mid] 时说明区间长度 ≤ 2。此时有两个元素相等意味着 low 和 mid 是同一个位置（或数组长度 2 且两元素不等时，== 的情况反而没出现），所以用 <= 是安全的——它只是把少元素的情况归入左半边有序分支，实际不会产生歧义。

错误写法分析

// ❌ 错误一：只比较大小，忘了结合区间值域判断
if (nums[low] < nums[mid]) {
    if (nums[mid] > target) {
        high = mid - 1;  // 直接认为在左边 —— 错误！
    } else {
        low = mid + 1;
    }
}

反例：nums = [4,5,6,7,0,1,2], target = 0

  • low=0, high=6, mid=3, nums[mid]=7
  • nums[low]=4 < nums[mid]=7 → 认为左边有序
  • nums[mid]=7 > target=0 → 错误地走左边（high = mid - 1），但 0 在右边
  • 原因：只比了 mid 和 target 的大小，没检查 target 是否落在 [nums[low], nums[mid]) 范围内

正确写法必须同时满足两个条件：有序区间的左边界 ≤ target < 有序区间的右边界（左闭右开）。

最终模板

int search(int[] nums, int target) {
    int low = 0, high = nums.length - 1;
    while (low <= high) {
        int mid = low + (high - low) / 2;
        if (nums[mid] == target) return mid;

        if (nums[low] <= nums[mid]) {         // 左半边有序
            if (target >= nums[low] && target < nums[mid])
                high = mid - 1;               // target 在左半边
            else
                low = mid + 1;                // target 在右半边
        } else {                               // 右半边有序
            if (target > nums[mid] && target <= nums[high])
                low = mid + 1;                // target 在右半边
            else
                high = mid - 1;               // target 在左半边
        }
    }
    return -1;
}

Find Minimum in Rotated Sorted Array（153）⭐⭐⭐⭐

  • 比较 nums[mid] 与 nums[high]
  • nums[mid] < nums[high] → 最小值在左半，high = mid
  • nums[mid] > nums[high] → 最小值在右半，low = mid + 1
  • 循环条件 low < high，终止时 low == high 即为答案

Find Peak Element（162）⭐⭐⭐⭐

不是在有序数组中找目标值，而是在「无序」数组中利用局部有序性找峰值。核心直觉：永远往更高的方向走，一定能找到峰值。

如果 nums[mid] > nums[mid+1]，说明左侧存在峰值（因为 nums[-1] = -∞，左侧是下降趋势，必有峰在 mid 或之前）；反之 nums[mid] < nums[mid+1]，右侧存在峰值。

算法思路

二分比较 nums[mid] 与 nums[mid+1]：

if (nums[mid] > nums[mid + 1]) {
    right = mid;         // 峰值在左侧（含 mid）
} else {
    left = mid + 1;      // 峰值在右侧
}

为什么不比较 nums[mid-1]？

  • 只比较 mid 和 mid+1 就足够了，因为 mid+1 一定在 [left, right] 范围内（循环条件 left < right 保证 mid < right）
  • 比较 mid-1 需要额外处理 mid == 0 的边界
  • 这道题 mid == 0 是合法的，所以即使比较 mid-1 只要处理边界也没问题，但用 mid+1 更简洁统一

时间复杂度

指标值
时间复杂度O(log n)
空间复杂度O(1)
循环条件left < right（因为 right = mid，不能排除 mid）
取整方式下取整 mid = left + (right - left) / 2（因为 right = mid）

附录：三个决策的推导原理

正文的「完整决策流程」是操作口诀；本附录解释它为什么正确：三个决策不是并列的自由选择，真正要判断的只有「mid 能不能是答案」（排除还是保留），循环条件和取整方向都被它锁定。推导依据只有一条不变量——每一轮循环都必须严格缩小搜索区间 [low, high]，否则就是死循环。

决策 1：循环条件（< 还是 <=）—— 问"区间最终能缩到空吗？"

  • 所有分支都排除（mid ± 1）：每轮至少减 1，最终缩到空 → 用 <=，退出时 low > high，答案已检查过或不存在。
  • 存在分支保留（= mid）：保留分支永远不删最后一个元素，区间最多缩到 1 个元素、缩不到空。若还用 <=，low == high 时仍会进循环，保留分支的赋值等于没赋 → 死循环；必须用 <，退出时 low == high，剩下的唯一元素就是答案。

决策 2：取整方向 —— 问"mid 会不会正好落在被保留的端点上？"

当区间还剩 ≥ 2 个元素时，mid 绝不能等于可能被保留的那个端点。看只剩两个元素 [k, k+1] 的极端情况：

  • 存在 high = mid（保留右端点）→ 必须下取整。若上取整，mid = k+1 = high，命中后 high = mid = high，区间没变 → 死循环。
  • 存在 low = mid（保留左端点）→ 必须上取整。若下取整，mid = k = low，命中后 low = mid = low，区间没变 → 死循环。
  • 全部排除 → 取整方向不影响正确性，惯例下取整。

口诀：保留哪一端，mid 就偏向另一端 —— 保留 high → mid 偏左（下取整）；保留 low → mid 偏右（上取整）。

两套合法模板（混搭必出 bug）

模板更新方式循环条件取整退出时答案在哪
排除式所有分支 mid ± 1<=下取整（随意）low > high（空区间）已检查的元素 / low / ans
保留式某分支 low = mid 或 high = mid<保留 high → 下取整；保留 low → 上取整low == high（单元素）就是剩下的那个元素

常见 bug 都是混搭：保留式更新 + <=（缩到单元素后原地转圈）；low = mid + 下取整（两元素时原地踏步）；排除式更新 + <（漏掉最后一个候选，如 69 的 V2）。
